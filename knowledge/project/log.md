## 2026-07-15

- **npm alias `create-ai-native-starter`** (CLI-repo folder `create-ai-native-starter/`, PRs #30 + #31-workflow). The requested `create-ai-native-app` was **already owned** by an unrelated npm publisher, so the alias is `create-ai-native-starter` (`npm create ai-native-starter`). It's a **thin wrapper**: `index.js` is one line — `import "create-ai-native-project/dist/index.js"` — which self-executes on import (the canonical CLI calls `program.parseAsync(process.argv)` at top level), so bare/`--boot`/`update` behave identically. It depends on `create-ai-native-project` with a **caret range** (`^1.3.0`), so new minor/patch releases of the canonical CLI flow through **without republishing** the alias — only a canonical **major** needs an alias bump. Published `1.3.0` manually (first publish can't use Trusted Publishing until the package exists; done via `npm publish ./create-ai-native-starter --access public --otp=…`, verified live via `npx create-ai-native-starter@1.3.0`). Added **`.github/workflows/publish-starter.yml`** for future releases: triggers on a `starter-v*` tag or `workflow_dispatch` (kept **separate** from the main `Publish to npm`, which fires on `vX.Y.Z` releases — so the alias isn't coupled to the main cadence), publishes with **OIDC Trusted Publishing** (`environment: release`, `id-token: write`, npm@11, `--provenance`) from the `create-ai-native-starter/` working dir. **User configures the npm Trusted Publisher** for the `create-ai-native-starter` package: repo `GeekyAnts/create-ai-native-project`, workflow `publish-starter.yml`, environment `release`.
